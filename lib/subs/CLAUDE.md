# `lib/subs/` — Netflix subtitle ripping + SRT (`subs`/`srt`)

The measured detail behind `gigaku subs`, `gigaku srt`, `gigaku spell` and `gigaku translate`. The map —
commands, shared layer, dependencies — is the repo-root `CLAUDE.md`.

## Modules

- `subs.py` — the whole `gigaku subs` flow (see below). The one module here that needs pyobjc.
- `excel_to_srt.py` — LR "Excel subs" xlsx (Time / Subtitle / Machine-Translation) → two aligned SRT files (`convert()`), plus `convert_exports()` behind `gigaku srt`. Pure logic; reads via openpyxl. Two things the export's shape dictates: LR **merges consecutive cues into sentence rows** (a measured 1220-cue track exports 862 complete rows), so `verify()` gates on the last **timestamp** reaching the last cue, never on the row count — counting rows can't tell merging from truncation and threw good exports away; and a title with official subtitles in your language exports a **`Human Translation` column before `Machine Translation`**, so both `verify()` and `convert()` pick the machine column by name (it's empty for ASR tracks, where there is no human translation).
- `library.py` — `index.json` for the subtitle library (`SRT_TARGET_DIR`, i.e. the `chrome/gigaku/subs/` folder), rewritten by both `subs` and `srt`. It exists because a Chrome extension can fetch its own files but **cannot list a directory**: `byId` maps the Netflix video id (which `gigaku subs` knows per episode) to an entry, `byTitle` keys `title|season|episode` for everything else, and both point at the same records so they can't drift. Ids from earlier runs survive a rescan as long as their episode is still on disk; the write is atomic (`os.replace`) because the extension may be reading it mid-rip. Pure stdlib, so the tests hit it directly.
- `episode_range.py` — `gigaku subs [N-M]`'s argument: `parse()` (shape), `select()` (bounds, against the real season) and `describe()` (the line printed before a rip). Pure, like `naming`, which is what lets the CLI answer a typo'd range without loading `subs.py`. See the "Which episodes" bullet below for why the two checks live apart.
- `srt.py` — read and write `.srt` (`Cue`, `parse`/`render`, `read`/`write`), plus `groups`/`regroup`, which cut an episode into request-sized windows with unasked neighbours on either side. Those two lived in `translate_prompt.py` while the glosser was the only pass over a Primary; they are about slicing cues rather than about any rubric, and the proofreader needs exactly the same windows, so they sit beside `Cue`. Nothing here read an SRT before the glosser: `excel_to_srt` only ever wrote one. A cue's **timecode line is carried through verbatim, never re-derived** — it stays a string, so replacing an episode's text cannot move its timings by construction. The write is atomic (a half-written Secondary is one the extension would load).
- `translate.py` + `translate_prompt.py` — **the Secondary track, glossed from the ripped German by Opus instead of machine-translated by Language Reactor** (`gigaku translate`, and inline in `gigaku subs` unless `SUBS_TRANSLATE` is off). What this removes from a rip is the expensive half: LR fetches translations line by line, **rate-limits a season** (90s of backoff, up to 8 times *per episode*), and a track revert mid-wait means it cheerfully translates the wrong track while nothing stalls. It also buys quality LR cannot — LR sees one line, this sees a run of them, which matters because the exporter cuts sentences mid-clause. **Alignment is by echoed id, never by position**: the reference implementation of this job (a third-party subtitle-translation prompt) separates blocks with a marker, matches positionally and *pads* a short chunk, so one merged block silently re-times every cue after it; asking for the id back makes the same event a **named gap** that is re-asked, and a cue physically cannot receive another cue's text (`lib/anki/prompt.py` made the same call for scoring). Requests are `SUBS_TRANSLATE_GROUP` (**50** since 2026-08-08, was 200) consecutive cues plus `SUBS_TRANSLATE_CONTEXT` (6) untranslated neighbours each side, so a seam is never a cliff — **context is load-bearing, not padding**: a fragment with no neighbour visible cannot be glossed at all. **50 is measured, and it cost something to learn.** Amortising the ~24k harness argues for the biggest request that fits, and 200 was that argument taken past its point: on one fixed 144-cue block a 200-cue request showed **4** German compounds by their parts where 50-cue requests showed **14**, collapsing the rest into single Russian words. But shrinking the group **broke name consistency**, because the rubric leans on the context lines to make the tenth mention of a name match the first — true while an episode was two requests, false once it is eight with six lines of context each. Measured on E14: «Бароу» against «Бару» inside one episode, five findings, plus a name left in Latin twice. Hence `translate_prompt.names()`: every request after the first is handed the capitalised Cyrillic words already answered, as an instruction not a word list. The extraction is crude on purpose and one-sided — a sentence-initial capital is dropped (or «Что» and «Ты» would crowd out the cast) and a common word slipping in costs one redundant reminder, while a name left out costs the inconsistency this exists to prevent. Answers are written to a work file in the cache **after every request** (a rate limit costs one request, not an episode — `lib/anki/score.py`'s lesson), keyed per episode and stamped with the rubric fingerprint, so a rubric edit re-does the episode rather than finishing it half in each wording. A line that never comes back **stops the episode** instead of landing as a blank; the Primary is untouched and `gigaku translate` resumes at the gaps. **On the way out, one more call puts every joined token into dictionary form** (`_normalise`, `SUBS_TRANSLATE_NORMALISE`) — and the reason it is a pass rather than a rule is the whole lesson of 2026-08-08. Seven rubric edits took bent tokens from ~17 per episode to ~6 and stopped there, and *how* they stopped is the tell: «команда_игра», anchored in the rubric, came back right six times out of six, while «мяч_приёмка» — also anchored — came back right in one line and as «мяч_приёмки» in the next, inside one episode. A rule the model honours for some occurrences and not others is not fixed by stating it an eighth time; it is glossing 350 lines and spending its attention on meaning, which is where it belongs. Asked instead about ~30 bare tokens with no scene, no German and no word order to weigh, the job is a dictionary lookup — the narrowest thing a model does. Measured: one call, ~$0.08, 9 of 27 tokens corrected on E14 and 31 of 61 on E12, and the substitution afterwards is plain string replacement so no timecode and no unjoined word can move. Three guards in `parse_normalise`, each answering a way the reply can be *wrong* rather than absent: only a token that was asked about (an invented pair can never enter the episode), only a reply with the same number of parts (a merge or a split is answering a different question — a form was asked for, not a re-gloss), and first answer per token wins. It is best-effort: a failure returns the lines untouched with a note, because a handful of bent tokens is not worth losing a glossed episode over. **A second pass runs before it** (`_unjoin`) and answers the prior question — whether a token should carry a mark at all. The underscore claims *these Russian words are the pieces of one German word*, so «рот_на_замок» and «пускающий_пыль_в_глаза» are false claims, and taking the mark off removes the claim without touching a word. It is the defect eleven rubric edits could not reach, for the same reason the dictionary check moved out: told not to join a Russian phrase, the glosser obeys on most lines and not on all, because it is reading a scene. The pass runs **first**, so the normaliser does not spend its answer on tokens about to lose their mark, and it is **one-directional by construction** — a mark can be removed, never added, so a confused reply cannot invent a compound. Measured across Blue Lock S01E12–24: 30 tokens split of 446, the season's phrase-joins falling 22 → 2, and «под_брос_машины» (three parts of one real German compound) kept every time. Together the two passes put the whole 13-episode season at **0.6 mechanical defects per episode**, from ~17 before any of this. Measured on Blue Lock S01E05 (379 cues): **2 requests, ~2 minutes, both complete on the first ask**. **A request answers in one of two deliberation modes, the mode is drawn per request rather than per run, and the fast one is measurably worse — 2026-08-07.** `lib/claude.py` already records that cost is erratic (1.8k–35k output tokens across eight identically-shaped calls); what that entry does not say is that for the glosser the spread is bimodal and tracks *quality*. Measured on E06, same rubric, same input: a request comes back at either **~2.7–4.2k output tokens in ~60s** or **~32–52k in ~9 minutes**, with nothing in between. On the identical 144-cue second request across three runs, the two slow answers found **14 and 15** compounds and the fast one found **4** — it silently collapses two thirds of them into a single Russian word, losing the half the rubric works hardest to keep, and it also produced an invented «— это» for `ist` that the rubric forbids outright. So **one run is not a measurement of a rubric change**: an A/B whose two sides drew different modes measures the mode. This bit for real in the same session — a held-out E07 run drew the fast mode, was read as "the new rubric barely helps", and the slow re-run of the same rubric answered with zero bad marks against the baseline's two. Judge a rubric on slow runs, or on several; and a fast-mode episode is worth re-glossing before it reaches the screen, which the joined-token count makes visible for nothing (`gigaku translate` does not yet check this — the run's own `out` figure and a low compound count are the tell). Opus, not Sonnet — A/B'd on one fixed 120-cue slice, same rubric, one request each: 39s against 314s and 2.2k output tokens against 24.9k (Sonnet deliberates, exactly as `gigaku clarity` measured), and Sonnet mangled a name *inconsistently inside one episode*, which is the worst failure this track can have.
- **The rubric is an interlinear gloss, not a translation, and that is the user's requirement** (2026-08-05). It is built on **one rule stated as a procedure** — walk the German line left to right, write each word's Russian counterpart in that same position — with everything else presented as a *consequence* of it. That structure is itself a correction: each review round turned up another reordering (verbs to the end, then clusters, then possessives) and each got its own rule, which is patching symptoms; `lib/anki/prompt.py` records the same lesson from the other side, where three rules that each patched the last one's damage swung its scores by 30–40 points until two were deleted. **Correspondence outranks Russian grammar** — broken Russian is the format, not a defect: no «не» is added to `Du weißt gar nichts`, a conjunction stays in the German's slot even where no Russian speaker would put it, and the copula is the single exception (write «есть» only where it reads as Russian). One German word gets one Russian token, compounds show every part **in the German's order** (`Blickfeld` → «взгляд_поле», not «поле_зрения»), joined by `JOINER` (`_`, substituted into the rubric text through a sentinel like `lib/pages.py` inlines its CSS, so changing it changes the rule, every example and the fingerprint at once). Sense — and only sense — comes from the scene. **The joiner's scope and the form of a part were both settled on 2026-08-07, watching an episode on the television rather than reading a file** — two things only the screen showed. **(1) Every part but the last stands in its dictionary form**: «игра_поле», never «игры_поле» (a genitive saying *of the game*, which no German part says) and never «игровое_поле» (a derived adjective, same objection); only the last part takes the case the sentence gives the whole word, so `Glasbein` is «стекло_нога» as a subject and «стекло_ногу» as an object. The rule this replaced — "which case-form each part takes is Russian's business" — was licensing exactly the restructuring the gloss exists to refuse. **(2) The mark is scoped by the Russian side, not the German one**: join only where leaving the words plain would have them read as separate words. «игра поле» would; «как раз», «в этом», «что ж», «между прочим» would not, so `gerade` and `da` get no mark. Measured before the change on E06: **63 joined tokens over 344 cues and 25 of them joining nothing compound at all** — that was the old rule ("where Russian genuinely needs two words, join them") working as written, and on screen it read as a broken file. A joined token must also be the German word's **own parts**: `Mitspielern` shows `Mit` and `Spieler`, never «товарищам_по_команде», and `fällt … auf` is never «бросается_в_глаза» — the mark is a claim about a German word's pieces, so joining words that are not its pieces tells the reader something untrue. Two consequences of that had to be written down after the first pass over-corrected into them: an **idiomatic** compound takes one Russian word (`mithalten` → «поспевать», `kaltmachen` → «обезвредить`; with a separable prefix one word is the default and showing the parts is what must earn its place), and **every part must be a word, never a Russian prefix** — «раз_ломать» is the single word «разломать» with a mark dropped into the middle of it. **Every worked example is checked position by position, and that was a real failure**: four anchors had been written in an earlier round and still showed the word order the rules forbade, so the rubric was teaching the mistake, and examples outweigh rules. A rule with only a formulation held about half the time; the same rule with a worked example held. **It happened a second time on 2026-08-07 and was found by machine, not by reading**: the `Du gehst mir ganz schön auf die Nerven` anchor rendered `ganz schön` as the single word «порядком», so the rubric was demonstrating a dropped word while forbidding one three sections above — and the audit caught the model doing exactly that twice in one episode. An intensifier pair is the easiest place in the language to lose a word unnoticed, because the surviving word already carries the whole sense. The same pass found a shape the rubric had never named at all: it said where a Russian word goes when German splits **auxiliary + participle** and was silent on the **separable verb**, which is the commoner split (`Los, wir halten sie auf!` → «Давай, мы их останавливаем!» — the word goes where the *prefix* is, for the same reason it goes where the participle is).
- **The loop that produced those findings, and the one measurement rule it taught.** A round is: edit the rubric → re-gloss one episode → `joiner.py` (mechanical, one second) → `audit.py` (an adversarial LLM reviewer, ~18 min for 344 cues, scoring against the current rubric's rules and reporting `id | CATEGORY | what | corrected line`). The mechanical half is what makes it usable — a German compound's parts are content words while a fixed Russian phrase is held together by a function word, so classifying every joined token needs no model. **Two things about the reviewer must be remembered before trusting it.** It has to be rewritten whenever the rubric is, or it drags the next round back to the round before: the version left over from the E05 rounds still demanded grammatical Russian and «игровое_поле», both since reversed. And it **contradicts itself between runs on questions of register** — it wanted «мужик» over «блин» in one round and «блин» over «мужик» in the next, and it demanded a proper name be joined — so `LEX` findings on interjections are noise, and a finding is only actionable when it names the German word that moved. **The measurement rule: tune on one episode, then validate on one you never looked at.** E06 fell from 25 wrong marks to 0, which looked like a result about the rubric and was a result about E06 — held-out E07 had only 2 wrong marks to begin with, and Vinland Saga E05 had none. What generalised is visible only on the held-out runs: `Schlachtfeld` → «битва_поле» in a show the rubric never mentions, and the *old* rubric's zero marks there turning out to be zero **compounds shown at all** — it had been collapsing them into one Russian word and losing half of each. The harness is scratch code outside the repo, parameterised by `SHOW`/`EP`; re-create it from this description.
- `spell.py` + `spell_prompt.py` — **the ripped German is proofread before anything reads it** (`gigaku spell`, and inline in `gigaku subs`/`gigaku translate` unless `SUBS_SPELL` is off). The Primary comes from LR's *ASR Pro German*, a machine transcript, so the Russian would otherwise be glossed from the transcriber's guesses. **What is wrong was measured before a line was written, and it is not what it looks like**: over the 165 ripped episodes (72,525 cues, 2.88 MB) Language Reactor's export is byte-faithful — **0** mojibake, **0** stripped umlauts (34,071 `ä/ö/ü/ß` all present), **0** run-together words, **0** `ss` for `ß`, **0** markup, apostrophes normalised curly→straight and nothing else. Nothing is wrong with the export; the transcript is what is wrong, in four classes with very different sizes. **A name spelled differently every time it is said is by far the biggest and the one the reader sees**: `Esdeath` 28× beside `Esteth` 13×, `Estef` 10×, `Estet`, `Esdeth`, `Esteph`, `Estep` — ~28 minority occurrences an episode across the corpus, also `Sihon`/`Siheon`/`Si-heon`/`Sihun`, `Tatsumi`/`Ttsumi`/`Tatsomi`/`Tatsumee`, `Kaiserwaffe`/`Kaiserwassen`/`Kaiserwappe`. Then ~3–5 ordinary misspellings an episode (`unernwartet`, `zerstöckelt`, `Medikement`, `Prinzessine`, `desqualifiziert`), ~2.4 nouns left lowercase (`ankunft`, `kinder`, `königreichen`), and homophones, which are **rare** — 69 `, das ich…` for `dass` in the whole corpus. **Every line is read**, in `SUBS_SPELL_GROUP` (100) windows with `SUBS_SPELL_CONTEXT` (4) unasked neighbours; the cheaper design that was measured and rejected is written up under "the nominator" below. The reply is `id: OK` or `id: ` and the corrected line, matched on the echoed id, and **an unanswered line is a keep rather than a gap** — the deliberate opposite of `translate.parse`, because the cue simply stands as it was ripped, which is the state the file was already in.
  - **The guards are backstops, and the first version of them was wrong in a way worth keeping.** They budgeted the whole line's letters at `len // 8`, which on `Esteth kam allein.` is one edit — and `Esteth → Esdeath` is two. A line-length budget refuses the commonest correction in these files on short lines and waves it through on long ones, which is exactly backwards; it was caught by a smoke test one minute after being written, and only because the smoke test used real examples rather than invented ones. The budgets are now split into **how much of the line moves** (at most `max(2, words // 6)` runs may change) and **how far each piece moves** (`MAX_WORD_EDITS` = 3 letters per changed run, compared case-insensitively so a capitalisation fix costs nothing). Together they make a paraphrase, a translation, an appended clause and a swapped word inexpressible while letting through every measured real correction — `Göttinn→Göttin` 1, `Medikement→Medikament` 1, `gegens→gegen das` 2 — and refusing `Incursio→Inquisition` at 6.
  - **The series name ledger, and why a threshold cannot build it.** The ledger is `{correct spelling: [misspellings of it]}` for a whole show, handed to the request as names already settled *and* to `refuse` as names that may not be respelled. Clustering the variants by string similarity was tried first and **measured to be impossible**: the pairs that must merge score 0.50–0.92 (`Esdeath`/`Estef` **0.50**, `Esdeath`/`Esteth` 0.77, `Tatsumi`/`Ttsumi` 0.92) and the pairs that must not score 0.25–**0.80** (`Koro`/`Kuro` 0.75, `Enma`/`Emma` 0.75, `Kurome`/`Kuro` 0.80 — while `Nagenda`/`Narzenda` 0.80 *should* merge). The ranges overlap completely, so every cutoff either leaves `Estef` uncorrected or renames a character — and here that is fatal rather than disappointing, because a wrong group **protects a mistake in every episode of the series at once**. So a model groups them, in **one call per series** cached under the candidate list's own hash, asked the narrowest question there is: a list of words and their counts, no scene, no grammar. Two mechanical guards stand under it — only words that were listed may appear, and **the most-written spelling of a group is the canonical one whatever the reply says** (a correction, not a refusal: the grouping is what is hard, the majority is arithmetic the caller already has, and letting a reply promote a rare spelling is the one way this could make a whole series worse at once). Candidates are capitalised words that are **not** sentence-initial and that macOS's German dictionary does not know; without that filter the loudest clusters in the corpus are grammar (`Wenn`/`Denn`, `Wie`/`Wieso`, `Meine`/`Eine`/`Deine`). Built from every Primary of the show on disk, so a sweep's first episode knows the cast as well as its last.
  - **The nominator, and why it is not the design.** macOS's `NSSpellChecker` (German, via the already-declared pyobjc) flags ~63 tokens an episode, and a cheaper pass — nominate mechanically, decide each in one call — is ~8× cheaper. It was measured and **rejected by the user on 2026-09-04** with the price in front of them, because it cannot see a homophone, a missing capital on a word the dictionary knows in lowercase, or a name that is *consistently* wrong. The dictionary stays, in the two roles it is actually good at: its doubts are **listed** in each request (never marked inside the German — a marker inside the text is a character the model can echo back into the file), and its before/after count is journalled as a free standing alarm, since a pass that raises it is inventing words. **Its suggestions are never passed on at all**: measured, it wants `Barou`→`Balou`, `Susanoo`→`Susana`, `Reo`→`Leo`, `Midgar`→`Midgard` — reaching for the nearest word it knows, which is the exact mistake this pass must not make.
  - **The record, and the one thing here that is not best-effort.** `.orig.srt` (a byte copy of the ripped Primary, written **before the first request** and never overwritten by a later pass) and a journal of every edit with the line it replaced live in `~/Library/Caches/gigaku/subs-spell/`, never in `chrome/gigaku/subs/` — a sidecar there would be invisible to `library.scan` *and* survive `excel_to_srt.trash_existing`, which matches the same pattern, so it would be permanent debris in a directory the extension serves. Write order is `.orig.srt` → journal → Primary, and a failure to write either of the first two abandons the pass with the German untouched: a correction with no receipt is the state that must not exist, and the reverse order would leave a corrected file with no way back. Three hashes guard it: the rubric `fingerprint` (an edit re-reads the episode), `result_sha` (`--revert` refuses an episode whose Primary has moved since) and `source_sha` (matching neither means a fresh rip, and the record is discarded rather than half-trusted). Everything else is best-effort — a missing `claude`, a missing dictionary, a refused answer — and ends with the German exactly as ripped and a note saying so, because the Primary is already on disk and readable and a proofreader that could *fail* an episode would be a new way to lose work the browser already paid for.
  - **The ledger read its own output, and the loop hid itself — found mid-sweep, 2026-09-04.** `_show_cues` fed the ledger the *live* Primaries, so once a sweep began correcting a series it was counting spellings its own edits had rewritten. Measured on A Time Called You: the ripped text has `Sihon` **11** against `Siheon` **12** — a one-vote margin, which is a coin toss, not evidence — and five episodes later the same count read **4 against 33**, a gap the pass had manufactured entirely from its own corrections. It had picked the right name (Nam Si-heon) and that was luck; a wrong first choice would have been confirmed just as hard and just as silently. Two more failures fell out of the same loop and are the reason it was *visible* at all: the candidate list changed after every episode, so the cache key changed, so the ledger was **re-asked once per episode instead of once per series** (6 calls for 6 episodes), and because corrected variants drop below `LEDGER_MIN` the ledger **shrank as the sweep ran** — 6 settled names at episode 1, 3 by episode 5, so the last episode of a season was proofread with half the protection of the first. The fix is one line of intent: **the ledger reads the ripped German** (`.orig.srt` where this pass has been, the live file where it has not, which is the same text). That kills all three at once and makes a re-run reproduce the ledger it had before, which is what lets a rubric be A/B'd at all. Confirmed in the restarted sweep: one ledger call per series. **The second fix is `MAJORITY`**: the caller now overrules the reply's choice of canonical only when the most-written spelling is at least twice as common. Overriding a model that can read Korean romanisation on an 11-vs-12 margin is overriding it with a coin toss; the guard exists to stop a *rare* spelling being promoted, and 11-vs-12 is not rare.
  - **Two more ways the ledger went blind, both found by auditing a live sweep rather than by reading code — 2026-09-04.** Each was invisible in the output as a *wrong* edit; each showed up only as a name the pass kept getting wrong. **(1) One floor for two jobs.** A spelling had to be said `LEDGER_MIN` (3) times to be a candidate at all, so a mishearing heard twice was never offered to the ledger. Measured on Crash Landing on You: a character is `Samsuk` 4 times and misheard as `Samsung` 2, `Samso` 2, `Sambuk` 2 — no mishearing cleared the floor, no cluster formed, the ledger said nothing, and the pass repaired **1 of the 4** occurrences from context alone. A variant heard twice is still a variant; it is the *canonical* that must be well attested, because it gets imposed on every episode. Hence `VARIANT_MIN` (2) for membership and `LEDGER_MIN` for the head, with a group whose own canonical is thin dropped entirely. **(2) A name that is also a German word.** The dictionary filter is what keeps grammar out of the ledger (`Wenn`/`Denn`, `Wie`/`Wieso`), and it also hides any name that collides with a real word. Measured on Move to Heaven: the protagonist is written `Guru` **26** times and `Guro` **10**, `Guru` is the German noun, so only `Guro` was ever a candidate — and the pass moved three occurrences *from the majority spelling to the minority one*, making the show less consistent than it found it. `Samsung` has the same shape. Dubbed Korean and Japanese names land on German words constantly, so this is not an edge case. The fix keeps the filter and makes the unknown words **seeds**: a word the dictionary knows is pulled in when it sits within a few edits of one, bringing its own count, so `Guru` arrives with 26 and outranks the seed that found it. **The slack has to scale with the seed's length and that was measured too** — a flat two edits pulled **78** ordinary German words into Crash Landing on You's 51 candidates (`Bad`, `Bein`, `Berg`, `Bier`, `Boot`, `Boss`), which is the flooding the filter exists to prevent; scaled by length it pulls 8, and Move to Heaven's 3 include `Guru`. The other half of the fix is in `parse_ledger`: a pulled-in German word becomes canonical **only with the `MAJORITY` margin over every rival**, so `Guru`(26) takes the name from `Guro`(10) at 2.6× while `Serie`(14) cannot take it from `Seri`(9) at 1.6× — and a group with no non-German spelling settles nothing.
  - **What auditing a sweep is actually for.** All three ledger defects above were found this way and none of them would have been found by reading the output for wrong edits, because **none of them produces one**: the precision stayed at zero errors in 713 changes throughout. They produce a name the pass keeps getting *right in one place and wrong in another*, which only a per-show count makes visible. The triage tool answers that question in a second and the model is not involved; use it, and read `NAME!` every time.
  - **Wall-clock, measured on the sweep rather than on one episode.** 96 episodes ran at **~2.1 minutes each**, so a whole 47,500-cue library is **~3.4 hours**, not the ~34 the single-episode extrapolation predicted — E19 had drawn slow-mode requests, and `lib/claude.py`'s erratic-cost note applies to time as much as to tokens. Estimate a sweep from a sweep. Over the first 11 episodes: **154 word-level changes, zero wrong**, and the cue-count-and-timecode invariant held on every one.
  - **The triage tool, and the flag that had to be taught twice.** `out/audit_spell.py` (scratch, gitignored — re-create it from here) reads the journals, checks the hard invariant, and buckets every change so only the risky ones are read. Its `NAME!` flag was wrong twice in a row and both corrections are the whole lesson. First it flagged any capitalised token said 3+ times — which is the exact shape of the defect the pass *fixes*, so it fired on 34 correct name repairs; a flag that fires on the intended behaviour is not an alarm, and the question that separates them is which *way* the change goes (towards a settled name, or away from one). Then it fired on `Ihr → ihr` and `Tod → Tot`, both correct and both ordinary German, so it also has to require that the word is one **German does not have** — a real German word is not a proper name being corrupted, however often it is capitalised.
  - **First measurement, Akame ga Kill! S01E19 (262 cues), two runs — 2026-09-04.** Run 1: **12 fixes, 1 refused**, ~$1.00 including the once-per-series ledger call; run 2 (`--redo`, so it re-read the ripped German): **11 fixes, 0 refused**, ~$0.72 with the ledger served from cache. **Every one of the 23 corrections across both runs is right, and not one name was corrupted** — the hard gate. Mechanically verified against the cached original: 262 cues in and 262 out, every index identical, **every timecode byte-identical**, exactly 12 text lines different, 2 bytes of file-size delta. The dictionary count fell both times (50 → 42, 50 → 43) and never rose, which is the free standing alarm working: a pass that invents words raises it. What the fixes look like: `Tatsumee`/`Datsumi`/`Katsumi`/`Tatsume` → `Tatsumi`, `Esteth`/`Estep` → `Esdeath`, **`Susanne`/`Susann` → `Susanoo`** (the ASR had turned the name into a German woman's), `Bößen` → `Bösen`, `Füsse` → `Füße`, `Befeil` → `Befehl`, `kräumen` → `krümmen`, `törig` → `töricht`. Note `Datsumi` and `Katsumi` were **not** ledger variants — they fall under `LEDGER_MIN` — and were fixed anyway, because naming the canonical spelling is enough; the ledger does not have to enumerate every mishearing.
  - **What the second run measured, which one run could not.** Ten fixes were **character-for-character identical** across both runs — the stable core. Line 15 (`Estep → Esdeath`) appeared in both and was *refused* in run 1: that is the guard change between them, not instability, and it is why the settled-name exemption exists. The genuine wobble is two lines, `kräumen → krümmen` and `törig → töricht`, found in run 1 and missed in run 2. So the instability here is **recall, not precision** — the dangerous direction scored zero twice — and the answer to it is the rubric, never re-running and merging: both words were in the request's dictionary list and were simply read past, which is a prompt to sharpen rather than a pass to repeat. **Judge a rubric edit on two runs at least** (`lib/claude.py`'s erratic answer, `--effort high` notwithstanding), and validate on an episode from a show the rubric was never tuned on — E06 falling 25→0 was a fact about E06.
  - **Where it runs, and why `--no-translate` gets none of it.** First statement of `subs._gloss`, so it is on `_Glosser`'s worker rather than the browser's critical path, and outside `_export_episode`'s attempt loop so a missing `claude` can never send the run back to Language Reactor. `_gloss` is only reached under `if glossing:`, which makes "`--no-translate` needs no `claude` on PATH" true **structurally** rather than by a second switch that can drift; `--no-spell` is the narrower escape hatch. `gigaku translate` runs it too, at the head of its per-episode loop, since an episode reaching that command is usually one whose rip finished and whose gloss did not. **The Russian of an already-glossed episode is deliberately left alone** (the user's decision of 2026-09-04): `translate.py` keys its work file on the filename and never hashes the German, so it cannot notice, and `gigaku spell` therefore *names* the episodes whose German moved under an existing Secondary instead of acting on them.
- `naming.py` — the single title→filename helper (`sanitize`, `srt_base`) shared by `subs` and `excel_to_srt`, so a season lands in **one** directory whether ripped or hand-converted. They used to sanitize a title *differently* (space vs dash) and silently split it in two; one helper is what keeps them in step. `lib/subs/__init__.py` imports **nothing**, so importing `excel_to_srt`/`naming` (the pure-logic path, and the tests) never pulls in pyobjc.

## `gigaku subs` — how it works

Drives Language Reactor's own in-page controller (`window.lln`) + Netflix's player metadata via AppleScript `execute javascript`. No cursor/screen-coordinate automation.

- **Two JS worlds.** `execute javascript` runs in an **isolated world** — shares the DOM but *not* page globals (`window.lln`, `netflix`). DOM work (the LR export dialog, `lln-*` classes) goes through `_njs()`. Page globals go through a **main-world `<script>` injection** (`_run_main()`): inject a `<script>` that computes a result and writes `JSON.stringify(...)` into a shared hidden DOM node, then read the node back. Netflix's CSP permits this. Migaku's `#MigakuShadowDom` overlay is hidden during the export dialog and restored after. All AppleScript calls are serialized by `_JS_LOCK` (a background pause thread drives the browser concurrently; NSAppleScript isn't thread-safe).
- **Track selection is via LR's API**, not Netflix's on-screen menu: `lln.vidMan.setSubtitleTrack(new_track_id)` / `setAudioTrack`. "ASR Pro German" is *not* a native Netflix track — it's the `type:"asr"` entry in `lln.subManager.data.mm.textTracks` (id starts `ASR_`, Pro-gated). LR is glitchy, so the set is clicked several times and **verified** by reading `data.tm` back — **type *and* name**: asked for ASR German, LR will happily land on ASR `Korean [Original]`, and a type-only check calls that success and burns a whole load attempt before the hard gate rejects it. LR also **reverts** a set track seconds later (back to the title's default — e.g. `closedcaptions:Korean`), landing in a settled `SUBS_LOADED`/stable-count/wrong-type state that no amount of waiting moves; `_wait_subs`'s `renudge` re-clicks the track when a stall shows the wrong type (but not mid-generation, where re-selecting would restart it).
- **A revert during the long waits is caught on the tick it happens (`_TrackWatch`).** The stretch between loading the track and exporting is the longest part of an episode — ASR coverage, then thousands of machine translations, then rate-limit backoff — so a revert lands inside it routinely, and it used to be noticed only by the verify *after* all of it (`tracks drifted to closedcaptions:Korean before export`). By then LR had fetched a translation for **every line of the wrong track**, all of it discarded, and the re-select paid for the whole wait a second time. So `_wait_asr_complete` and `_wait_translations` carry the track in their measurement (`_COVERAGE`, `_MT_STATE`) and re-select on the spot. Three things this has to get right: it cannot ride on `on_stall`, because while LR sits on the wrong track **nothing stalls** — it is busy translating Korean and the counts climb happily, which is why `_wait_progress` grew `on_measure` (after every measurement, before `done`); the two waits must not *believe* the wrong track either, since the title's default is complete from its first second and would satisfy both checks instantly; and the repair is **bounded** (`DRIFT_LIMIT`), because re-selecting forever against an LR that reverts every few seconds would never stall either — an oscillating count reads as progress — so past the limit the episode goes to the retry loop, which reloads. `_wait_translations`'s opening probe is guarded too: a revert that landed before the wait started would otherwise have the nudge below it asking LR to translate the wrong track.
- **The export is read, not just labelled (`lib/subs/language.py`, `excel_to_srt.verify(language=…)`) — 2026-08-14.** Every gate above this one reads Language Reactor's *metadata*: `tm.type`/`tm.name` for the subtitle track, `am.name` for the audio. A label is not a reading, and The Eminence in Shadow proved it: E11 and E12 were written as German Primaries containing **Japanese**, with `set audio=German subtitle=asr:German (3 clicks)`, `✓ verified`, the coverage gate, the end-timestamp gate and the row check all satisfied. Measured live on the same tab afterwards, which is what identified it: the player's audio really *was* German (`getAudioTrack() → German`) and LR's `am` agreed — so the audio side was never the problem — while LR's loaded text track was `closedcaptions:Japanese` holding **392 cues, exactly the 392 that landed in E12's Primary**. LR reverts on its own clock (see `_TrackWatch`), and the one gap nothing watched is the last one: `_verify_tracks` → `_seek_start()` → export. The **rewind is what makes LR rebuild**, so that gap is where a revert is *likeliest*, and it is the only stretch with no per-tick guard because there is no wait there to hang one on. What made it worse than a wasted episode: **resume keys on the Primary existing**, so a wrong-language Primary is skipped forever — re-running would never have re-ripped those two, and the season would have sat there silently half Japanese. Two changes, in the order they act. **(1)** A second `_verify_tracks` **after** the rewind — one call, and it was expected to catch the common case. **It doesn't, and the re-rip measured that within the hour:** E11 attempt 1 printed `✓ verified audio=German subtitle=asr:German n=267`, passed the pre-rewind recheck *and* this new post-rewind check silently, and still exported the Japanese captions (4,355 letters, the same file byte-count as the quarantined one). So LR's `tm` is not merely *late* — it reads the wanted track at the moment of export while the export dialog writes the other one, and **no label check, however late it runs, can catch this**. It is kept because it costs one call and still answers the older, visibly-different failure (`tracks drifted to closedcaptions:Korean before export`), but it must never be mistaken for the guard. **(2)** The file's own text, checked in `verify()` — the one thing a reverted track cannot fake, and on this specimen the only thing that worked. It cost one wasted export and the retry came back German (267 rows) on attempt 2, so the failure is per-export-attempt and a retry is a sufficient cure once something can *see* it. **What is still unexplained is when it strikes**, and the one clue worth keeping is E12's: it failed **all three** attempts of one run — each verifying `asr:German` with 315 cues loaded, each exporting a byte-identical 392-cue Japanese file, and the retry loop's `_reload_page()` between them changed nothing — and then came back German **on the first attempt of a fresh run**, at exactly the 315 rows the label had claimed all along. The difference between the two runs was not the page (both reloaded) but Language Reactor itself: the failing run had had LR on for hours and a dozen episodes, the passing one switched it **off and on**. That points at LR's parsed state going stale within a long-lived session rather than at anything per-episode, and the cure it suggests is to **restart LR rather than reload the page** when the language check refuses. That is now what happens (`WrongTrack` → `_recover_episode` → `_restart_lln`), and the reasoning for shipping it on one observation is worth keeping straight: this is not a claim, it is a **bounded, self-verifying** retry step. It fires only on the wrong-track refusal (never on a stall or a truncated export), it costs a couple of seconds, it cannot turn a good export bad, and the attempt that follows is judged by exactly the same language check as the one that failed — so if the cure is wrong, the episode fails as it did before and nothing else changes. `NF_lingoActive` is persisted, so the reload after the toggle brings LR up already on and engaging from the start, which is the shape the successful run had. **If a second measurement contradicts it, delete the branch** — the failure class is still caught, because catching it was never this step's job. The failure class is recognised by `excel_to_srt.WRONG_TRACK`, a shared constant rather than a matched sentence, so a reworded message cannot silently stop routing to it. It is a **script** check, not language detection: German is Latin end to end and Japanese ASR is kana end to end, so the margin is the whole alphabet rather than a threshold worth tuning (measured on the real files: E11 **0% of 4,355 letters** Latin, E12 0% of 4,753, E10 accepted). It refuses only what it is sure of, the rule `lib/vocab/ankimorphs.py::_lang_of` already follows — a language whose script isn't in `LANGUAGE_SCRIPTS` and a sample under `MIN_LETTERS` (200) both pass without comment, so passing a `language=` can only ever *add* a certain refusal. It lives in `verify()` rather than after the conversion because that is where "may this xlsx be trusted" is decided: a refusal drops the download and retries the episode, and **no SRT is written**, which is what keeps resume from skipping it. `gigaku srt` passes no language — it cannot know one — and is byte-identical to before.
- **Runs entirely in the BACKGROUND — no focus stealing (`_SPOOF_VIS`).** Netflix tears the player down / won't switch or generate ASR in a hidden tab, so instead of forcing the tab foreground, `_run_main` prepends a **page-visibility spoof**: it overrides `document.visibilityState`/`hidden` to always report *visible* and swallows `visibilitychange`, in the page's MAIN world, re-asserted on every call (a reload wipes it). Netflix then keeps playing/switching/generating while the tab sits in the background, so the user launches `gigaku subs` and **keeps using the computer** (switch tabs/apps freely). Navigation targets the tab **by URL** (`_chrome_tab`/`_goto`/`_reload_page`), never "active tab", so focus is irrelevant. `DisplayWakeLock` keeps the display awake so playback keeps buffering. **Stop:** Ctrl-C in the terminal, or close the tab. Re-run **resumes** at the next episode. (History: earlier versions instead *stole* focus / aborted-on-hidden — that fought the user and broke the moment they looked away; the spoof replaced it.)
- **What ends a run is *asked*, never inferred from an error string (`_tab_state`/`_check_tab`).** Every auto-stop funnels through one check, and it used to be: run JS on the tab, and if AppleScript answers "…not found in Chrome" (error -2700), call it *tab closed*. That error means only "no tab's URL contains `netflix.com/watch`" — which is equally true of a tab **Netflix bounced itself** to `/browse`, a title page or a login/error page. So a run nobody stopped ended with "Stopped (Ctrl-C or tab closed)", which was simply untrue, and threw away a recoverable season. Now `_tab_state()` asks Chrome one question and gets one of three answers — `watch` / `away` (a Netflix tab that isn't on a watch page) / `gone` — and each has its own consequence: **`gone`** stops the run and says so; **`away`** is *not* a stop but `_recover_tab()`, which steers that tab back to the episode (`_WATCH_URL`, the wide `NETFLIX_MATCH`) and raises `ExportError`, so the load/episode retry loops rebuild the page exactly as they do after any other stumble — only a tab that **won't** come back aborts, naming the URL it went to instead. A single reading never decides anything either (`_confirm_tab`, 4 tries × 2s): a run can be hours old and cannot resume mid-episode, so one unlucky probe — Chrome busy, a page swapping documents — must not be what ends it. `tests/test_subs_tab.py` pins the three answers apart.
- **The video NEVER plays — not even to generate ASR.** A background **pause-keeper** thread forces the video paused ~1×/s for the whole run (LR/Netflix keep resuming it on their own), and `_PAUSE_KEEP` is cleared only when the run ends. Earlier versions briefly played the video for fresh ASR, believing generation only progressed while the audio buffered. **That is false, and measured:** on a never-touched episode, force-paused at `currentTime=0` the entire time, LR still generated — 59 cues after 25s, 275 after a few minutes, `paused=true` throughout. Generation is server-side and progresses on its own, so nothing in the flow calls `play()`. Don't reintroduce playback: the whole point is that a rip is silent and invisible while the user keeps working.
- **Always resolve the *current* player session (`_PLAYER`).** All player control (pause/play/seek) and the movie-id gate resolve the session for the episode **in the URL** — the entry in `getAllPlayerSessionIds()` whose `getMovieId()` matches `location`, skipping closed ones — *not* `[0]`. Right after navigating, Netflix keeps the previous episode's session around and their order isn't stable, so `[0]` can be a stale/closing player: targeting it silently no-ops pause (episode won't stay paused) and makes `mid == expect_id` never match even though LR already loaded the right subs (`_wait_subs` hangs at `SUBS_LOADED`). This bit episodes mid-season (e.g. E23).
- **Adaptive waits, reload-to-recover, nothing fatal.** Waits poll for progress (subtitle state/count/track-type, translation count, a new download) and block while progress continues; on a stall they reload the page and retry (LR/Netflix get stuck constantly). No fixed per-step timeouts. Transient AppleScript errors (`AppleEvent timed out`, error -1712) are retried in `applescript.run` and, together with `ExportError`, are caught by the load/episode retry loops — a hiccup reloads-and-retries instead of crashing. A whole episode that still fails after its retries is **logged and skipped** (reported at the end; re-run retries it) rather than killing the season. Translations come from `lln.subManager.data.mTranslations` (complete when key count ≥ subtitle count), and completion must read true **twice in a row** — LR rewrites `subtitles` and `mTranslations` independently, so a single reading can land while the count dips. **LR's translation backend rate-limits** a season-length rip: it stops filling `mTranslations` and shows `Problem fetching translations. RATE_LIMIT_EXCEEDED` in `.lln-notification-content`. Reload-and-retry is exactly wrong there — it answers a rate limit with more requests — so `_wait_translations` recognises the toast and *waits it out* (`RATE_LIMIT_BACKOFF`, up to `RATE_LIMIT_MAX_WAITS` times). An `on_stall` returning True restarts the stall clock, so a deliberate backoff never counts as a stall. Episode list from Netflix's `videoMetadata._seasons[]._episodes[]._video` — Netflix's own, which is why the season can be announced before LR is touched.
- **Navigation is asynchronous — wait for the document to turn over.** `set URL`/`reload` return the moment Chrome accepts them while the *old* document keeps answering JS for a second or two. That document is fully loaded, so a state probe right after navigating reports `SUBS_LOADED` with the right movie id and every wait returns instantly against a page about to be destroyed — then the next call lands on the new blank document and dies with `lln is not defined`. `_navigate()` stamps the outgoing document (`window.__gigaku_page`, read back so a failed stamp can't fake success), navigates, and blocks until an *unstamped* one answers; `_goto`/`_reload_page` both go through it. `_goto` reloads when the tab is already on the target URL, so the document turns over either way.
- **A JavaScript dialog is the one failure that disables the machinery that would notice it (`_NO_DIALOGS`, `_EXPORTABLE`, `_clear_dialog_wedge`).** While an `alert`/`confirm`/`prompt` is up, Chrome answers **no** `execute javascript` on that tab — measured: a *non-JS* query about the same tab (URL, title, `loading`) came back in **0.1s** while `1+1` took **120.2s** to fail with -1712, which `applescript.run` then retries as a transient hiccup, so every JS call costs ~6 fruitless minutes. Every wait, probe and recovery path here is a JS call, so a run goes silent and stops progressing, which is what it was reported as ("it hung"). It happened for real on Blue Lock E14: a finished episode — right track, 416 cues, every line translated — met LR's **"Subtitles not loaded, no data to export."** the moment Export was clicked. That refusal is LR's own three-part gate, read out of its bundle rather than guessed: `state==='SUBS_LOADED' && data.tm.langCode_G && data.nlp`. `_verify_tracks` answers only the first (plus track names); `nlp` is LR's parse of the loaded track and is rebuilt after a track change or the **rewind this flow does immediately before exporting**, so there is a window where LR has the subtitles and won't export them. Three fixes, in the order they act. **(1)** `_export` waits on LR's own three conditions (`_EXPORTABLE`) instead of clicking into the alert. **(2)** `_NO_DIALOGS` joins `_SPOOF_VIS`/`_NO_PLAY` in the main-world prelude and **captures** `alert`/`confirm`/`prompt` instead of showing them — it reaches LR because LR's alerts live in `pageScript_lln.min.js`, a web-accessible resource injected into the page's **main** world (a content script's `alert` would be unreachable: every extension gets its own isolated world, including AppleScript's). Captured, not swallowed: `_dialog()` reads it back, so a refusal is logged in LR's own words and the late ones ("Error preparing export data…", "Export error: …") stop reading as a download that never came. **(3)** A dialog that lands anyway — the prelude only covers the page from the moment it is installed, and a reload wipes it — is recovered from by **replacing the tab**, because navigation does **not** clear one: measured, `reload` and `set URL` are both accepted, the tab then reports `loading` for ever with JS still blocked, while closing it clears it at once (JS answered in 0.2s from the fresh tab). The detector is the measured asymmetry — JS times out while plain AppleScript still answers about the tab — so `exec_js_on_extension` bounds every call in `with timeout of JS_TIMEOUT seconds` (a real call returns in milliseconds; this is a wedge detector, not a deadline) and `_njs` turns a -1712 into a reopen plus the recoverable `ExportError` the retry loops already answer.
- **The Secondary is glossed, not exported — so LR is never asked to translate.** With `SUBS_TRANSLATE` on (the default) the export dialog's Machine Translation box is left **unticked** (`_export_prep(want_mt)`) and `_wait_translations` is skipped outright; the Primary is converted, and `lib/subs/translate.py` writes the Secondary from it. That deletes the longest and least reliable stretch of a rip — see the rate limit and the revert-mid-wait failure below, both of which only exist because LR was doing the translating. A failed gloss is **not** an episode failure: the browser work is done and the Primary is on disk, so it is reported into `_UNGLOSSED` and left for `gigaku translate` (re-running the rip would skip the episode forever, since resume keys on the Primary). `--no-translate` restores the old path exactly, and is the one that needs no `claude` on PATH.
- **The gloss runs BESIDE the next episode's rip, not after this one's (`_Glosser`) — 2026-08-14.** The two stages share nothing: ripping is Chrome plus Language Reactor, glossing is `claude -p` against a Primary already on disk. Run in sequence they idled in turn — measured on The Eminence in Shadow, the browser sat still for the ~4 minutes of six Opus requests while the glosser sat still through the next episode's ASR generation — so a season cost the *sum* of the two where it need only cost the larger. `_export_episode` therefore **hands the finished Primary to a queue** instead of glossing it, and returns the moment the tab is free. **One worker, not a pool**: the rip is one Chrome tab and cannot be parallel at all, and the glosser deliberately isn't either — `lib/claude.py` records that parallel calls just get rate-limited, and a queue running ahead of the rip would pile up work whose input doesn't exist yet. So it is a pipeline of exactly two stages, one deep. Three things it has to get right. **Both stages narrate at once**, so `request 3/7` alone can no longer say whose episode it is: `lib/config.py` grew a **thread-local** tag (`noting()`, read by `note()`) rather than a parameter, because those lines come from deep inside `lib/subs/translate.py`, which knows nothing about running beside anything — and thread-local rather than global, or the two stages would stamp each other's lines. **A worker that dies strands every later episode**, the failure a bare `while True: get()` invites, so the loop catches everything and reports into `_UNGLOSSED` — `_gloss` already never raises, this covers the case where it manages to anyway. **The extension's index moves with the gloss, not with the rip** (`_index`), and this one was found only by checking the artefact afterwards: `library.scan` indexes a Primary+**Secondary** pair and nothing else, and `library.update` drops any id whose episode the scan didn't find — so registering right after the rip, which is now when only the Primary exists, silently loses the **Netflix id**, the exact locale-proof match the extension prefers over title+season+episode. Measured: five episodes indexed by title with no id at all. The registration is therefore a callback the glosser fires only when the Secondary was actually written (`_gloss` returns a bool for exactly this), and an episode whose gloss failed is never indexed, because an index entry for a pair that isn't there is a lie. The `--no-translate` path still registers inline, where both tracks land together. And **the ending has two shapes**: a finished rip drains the queue *after* the wake lock is released and LR is switched off (the browser's part is over, so the last episodes' Russian arrives with the tab already handed back), while a **stopped** run walks away from it — every answered request is already in the work file and `gigaku translate` resumes there, so Ctrl-C must not be made to sit through four more minutes of an episode nobody is waiting for.
- **A finished export ends with the PROGRAMME, and the check now measures it against that (`creditsMs`) — 2026-09-03.** ASR keeps transcribing over the **end credits** — the closing song, in whatever language it is sung — while LR's Excel export stops where the episode does. `verify` compared the file's last timestamp against LR's last *cue*, so a complete export read as three to five minutes short and was thrown away three times per episode: it cost a third of a 30-title run (Move to Heaven, Teach You a Lesson, Can This Love Be Translated?, The WONDERfools, The East Palace, Boyfriend on Demand, Elite), every one refused identically on all three attempts with byte-identical files. What settles it is **Netflix's own metadata, already loaded in the page**: the episode's `creditsOffset` — the second at which "Skip Credits" appears — under `videoMetadata[*]._metadataObject.video.seasons[*].episodes[*]` (the *same* `_metadataObject` pair `_season_episodes` reads the title from; `_seasons/_episodes/_video` does not carry it). Elite E01 exported to 52:04 against a `creditsOffset` of 52:36 with cues to 55:59; The East Palace E01 to 41:14 against 41:24 with cues to 45:29 — the export ends at the credits, to the second. The expectation is `min(last cue, creditsOffset)`, because an episode whose dialogue stops before the credits must still export every cue it has, and `CREDITS_GAP_MS` (the last cue before a 90s silence in the final quarter) is only the fallback for what has no marker — it would have kept rejecting Elite, whose closing song never pauses for more than 52s. **Three hypotheses died on the way and are not worth repeating:** the row count is not capped (379/416/580/695 across four rejected files), the character count is not capped (31k–58k), and `data.nlp` is not a parse to wait for — it is `{subs, wordFrequenciesSupported}`, one parse per cue, complete before the export. The tell that named it was the cue tail: after the last exported row came 97 seconds of silence and then an English song, `I'm saving your smile, my coded file`.
- **A full ASR queue is waited out, not reloaded into (`_asr_queue_full`, `ASR_QUEUE_BACKOFF`).** LR generates ASR on a shared, queued backend, and an hour into a 30-title list it starts answering `Problem fetching ASR subs. QUEUE_FULL` (seen on screen 2026-09-03, beside `RATE_LIMIT_EXCEEDED` for translations). Reloading answers a full queue with more of what it just refused, so `_wait_asr_complete` sits it out the way `_wait_translations` sits out the rate limit — the toast reader is now one function, `_lr_problem(pattern)`, asked two questions. The same run also stopped exporting on the first reading past `ASR_MIN_COVERAGE`: coverage is a floor, and the count must also sit still for `ASR_STABLE_TICKS`.
- **Output.** Per episode: LR exports one `.xlsx` to `~/Downloads`; the flow **verifies** it (it reaches the last cue's timestamp — plus, on the `--no-translate` path, that every subtitle line has a translation), converts it (`lib.subs.excel_to_srt`) into `SRT_TARGET_DIR/<Title>/<Title> - S01E03 - Primary.srt` (target language) + `… - Secondary.srt` (glossed, or LR's translation), then **deletes the xlsx only after** the check + conversion succeed, and refreshes the library index (`lib/subs/library.py`) with that episode's **Netflix id**. `SRT_TARGET_DIR` defaults to the `chrome/gigaku/` extension's `subs/` folder, so a ripped episode is loadable by Migaku the moment it lands — it is no longer `~/Downloads`. **Resume:** episodes whose `… - Primary.srt` already exists are skipped.
- **Which episodes (`gigaku subs 3-12`, `lib/subs/episode_range.py`).** `3-12` / `3-` / `-3`, inclusive; no range means the whole season, and resume still applies *inside* one (a range narrows the set, it never re-rips). **Resume is resolved before the banner, not inside the loop**, so the run opens by naming the episodes it is actually going to download — announcing the *requested* span and then skipping half of it is a promise about work nothing will do, which is why `describe()` takes both the todo list and the selection. It returns `(headline, rows)` of label/value pairs that `run()` aligns and prints one per line, and rows with nothing to say are left out: cramming it onto one line was measured against a real season and is unreadable. **Nothing is said twice, and the settings are a block of their own.** `Requested` appears only when it differs from `Ripping` — on a clean run `3-12` and `E03–E12  (10 episodes)` are the same sentence reworded, and it earns its place only once part of the range is already on disk and the ask can no longer be read off the row above. `Audio`/`Subtitle`/`Into` print as a **second block** after a blank line, sharing one label width so it stays a table: which episodes is the question the run is being asked, the tracks and the folder are how it will answer, and a single six-row list buried the first in the second. `spans()` collapses consecutive runs (`5–6, 9–12`), so the row stays short *and* exact when the leftovers are scattered — which after an interrupted season they usually are. **Bare numbers, no `E05`**: the row is labelled and the headline already named the season, so the prefix and the zero padding only crowded the one value on the line — the per-episode `=== E05 …` progress headings keep the `E` form, where it matches the filename. The numbers are Netflix's own `seq` — the `E03` in the filename — so `select()` filters on `seq` and never slices: a season whose `seq` has a gap would hand back the wrong episodes under `episodes[start-1:end]`. **A bare `5` is refused**, since "from 5 on" reads as naturally as "just 5" and guessing rips the wrong half of a season. The two error classes fire at deliberately different moments: *shape* (`3--12`, `0-3`, `5-2`) in `cli._subs_args`, before `lib.subs.subs` — and so pyobjc, and so Chrome — is imported at all; *bounds* (`4-9999999999`) only after `_season_episodes()`, because whether this season has an episode 12 isn't knowable until Netflix answers. That check sits inside `run()`'s `try/finally`, so a rejected range still restores LR's auto-pause and switches LR off. `gigaku subs [N-M] [AUDIO] [SUBTITLE]` keeps the old positional track args: argparse fills optional positionals strictly left to right, so `_subs_args` shifts by shape (a range starts with a digit or a dash, a track name never does). `-3` survives argparse only because no option string of that subparser looks like a negative number — adding a `-N`-shaped flag there would silently turn it into `unrecognized arguments`, which is why a test pins it.
- **A title page is enough — the run starts the player itself (`_start_player`).** `netflix.com/title/<id>` is where clicking a show lands you (and where `gigaku titles` sends you), so refusing there with "open a show at netflix.com/watch/…" was refusing over a tab already on the right show. Netflix resolves `/watch/<title id>` to the episode you would resume, itself — measured, `/watch/81159258` became `/watch/81205759` (episode 1 of *Crash Landing on You*) in under a second — so this is one navigation, not a Play-button click: nothing here can break on a redesign or an interface language. It runs before `_preflight_page`, and only for a title page: an actual watch tab needs no help, and `/browse` or no Netflix tab at all stays `_preflight`'s to explain. The wait gates on the `<video>` element, **not just the player session** — measured, the session answers ~2s before the element exists, and returning in that window hands back a page with nothing for `_pause` to pause. Polling with `_run_main` is what keeps it silent: every call re-asserts `_NO_PLAY`, so the episode Netflix just started is neutralised by the same loop that waits for it. Netflix sometimes redirects a title page to the player on its own (a part-watched show resumes); then `_tab_state` already says `watch` and this does nothing.
- **Preflight is two halves, and the split is what puts the banner before the waiting (`_preflight_page` / `_preflight_tracks`).** Everything the *page* has to offer — Chrome, the tab, the Netflix globals, the player — answers instantly, and **Netflix alone already knows the whole season**, so `_season_episodes()` reads the title from `videoMetadata[k]._metadataObject.video.title` (*not* `_video.title`, which is undefined — the same measured pair `chrome/gigaku` uses) and keeps LR's `mm.titles` only as a fallback. Language Reactor is the slow half: a cold toggle can sit at LOADING for minutes. So the page is checked, the season is **announced**, and only then is LR switched on and asked about Pro and the tracks — announcing it afterwards put the one thing the user is waiting to read behind the one thing they have to wait for. A run with nothing to fetch now skips waking LR at all, and `_get_autopause()` moves down with it (read before LR is on it just answers `None`, and the `finally` would then restore nothing). `tests/test_subs_tab.py` pins the order by capturing what has been printed at the moment `_preflight_tracks` is called.
- **Exactly one Netflix tab, refused before anything is touched (`_require_one_netflix_tab`).** Every step here reaches its tab by URL substring and takes the **first** match — that is what lets a run happen in the background with no focus and no window in front, and it is only a description of one tab while there is one. Worse, the halves of a run don't even match on the same substring: `_njs`/`_chrome_tab` use `netflix.com/watch` while `_tab_state`/`_start_player`/`_recover_tab` use the wider `netflix.com`, so with two tabs open one can be measured while the other is steered, and Chrome's own order isn't stable either — moving a tab between windows reorders the walk mid-run. What the wrong tab costs is not a failed export but the user's own episode: the run pauses the video, makes `play()` a no-op, takes over LR's track and switches LR off when it ends. So `run()` counts them first (`_netflix_tabs`, the same walk `_tab_state` does, kept whole instead of stopping at the first match) and refuses with **every URL listed**, ahead of `_start_player` — which navigates by the wide match and would otherwise be the first thing to grab the wrong one. A Chrome that won't answer is *not* this check's to diagnose: an `AppleScriptError` here returns silently and `_preflight_page` gives its own far better message. The count is a **precondition, not a watch** — a second Netflix tab opened mid-run is the user going back to using their computer, which is the whole design, and must not kill an hours-long season.
- **Preconditions:** exactly one Netflix `/watch` **or** `/title` tab open (auto-found by URL; two Netflix tabs is a refusal — see above), the Language Reactor **Pro** extension installed **and signed in**, and Chrome ▸ View ▸ Developer ▸ "Allow JavaScript from Apple Events" enabled. **Signed out and un-subscribed are one flag and two different fixes**, so the gate reads the store, not `proFeaturesEnabled` alone: a signed-out LR answers `{auth.haveAuth: false, data.licenseStatus: "NOT_SIGNED_IN"}`, and until 2026-08-20 that refused a whole season by telling a paying user to subscribe — the subscription was live and only the login was missing, which took a hand-probe of LR's own store to find. `licenseStatus` cannot decide it either: **signed in with Pro working it reads `"ZOMBIE"`** (measured the same evening, `pro: true` beside it), so only the `NOT_SIGNED_IN` reading is ever acted on and the refusal quotes it. **One reading settles it** — measured on a cold LR load, `pro` answers true from the first probe, 1.0s in and while `state` is still LOADING, because the auth store fills independently of the subtitle manager and never passes through a false phase; so there is no re-ask here, unlike every track check below. The gate stays scoped to the Pro half: signed out, LR still exports the free non-ASR tracks, and refusing those would refuse work that succeeds (`tests/test_subs_preflight.py` pins the two refusals apart). LR's **on/off toggle is handled automatically**: if it's off, `_preflight_tracks` switches it on (clicks `#lln-toggle-btn`, whose state is the persisted `NF_lingoActive` setting) and waits for the tracks to load; the run's `finally` switches it **off** again when done — so *every* run starts by switching LR back on, making that the normal path rather than an edge case. `_ensure_lln_on` waits for the **tracks**, not the switch: LR being on says nothing about whether it engaged (a Ctrl-C'd run leaves it on and still LOADING), and switched on mid-page it can sit at LOADING for **minutes** — with no intermediate state to measure, so the stall detector can't tell slow from wedged. Hence a long (90s) limit plus reload-and-retry: `NF_lingoActive` is persisted, so a reload comes up with LR already on and engaging from the start. A stray Netflix `M7037` error on the tab clears with a reload.

## Troubleshooting: the rip stops with "the Netflix tab was closed"

Since 2026-08-14 that message has a second, likelier meaning, and the run now says which one it
is. **Something outside Chrome can remove netflix.com tabs**, and when it does there is nothing
gigaku can do about it — a tab the system takes away cannot be held open by any amount of
retrying. Measured that evening, after a season had ripped happily for two hours:

- a Netflix tab opened by `gigaku subs` **loaded completely** — its title read `Watch The
  Eminence in Shadow | Netflix` 1.0s in — and was **gone from Chrome at 3.5s**. No navigation,
  no error page, no block page: the tab was *removed*.
- `example.com`, opened in the same window at the same moment, was still there a minute later.
  So it is netflix.com specifically, not new tabs in general.
- it happened identically in an **incognito** window, where extensions are off — which rules
  out the browser extensions and points at something system-level.
- Chrome itself had been running continuously for three days, so no restart ate the tab.
- it began between 19:57 and 20:00 that evening; before it, single episodes held a tab for
  tens of minutes at a time.

Two more measurements narrowed it and then it stopped on its own, which is worth recording so
the next hunt starts further along: **Safari kept a Netflix page open for 30s+ at the same
moment** (so it is not a system-wide website restriction — Screen Time would hit Safari first,
and no restriction store naming netflix was found), **no extension had incognito access** (so
the incognito result really did rule the extensions out), and **a second Chrome instance with
its own `--user-data-dir` kept its tab for a minute** while the main one was still killing
them. That leaves something scripting or restricting *this* Chrome specifically. By ~23:20 it
had stopped: AppleScript-created Netflix tabs survived indefinitely again. So it is
intermittent, it was never reproduced on demand, and the cause is still unnamed.

**What the run does about it.** A tab that dies inside `TAB_KILL_WINDOW` (30s) of a navigation
this run performed never had a chance to be closed *by the user* — they had nothing to look at
yet — so `_check_tab` no longer ends the season on it. `_reopen_tab` puts `_WATCH_URL` back and
raises the ordinary recoverable error, and the episode's own retry rebuilds the Language
Reactor state exactly as it does after any other stumble; `REOPEN_LIMIT` (5) caps it, and past
the cap the run stops and reports what was measured rather than blaming the user. This is what
turns the E16 ending — a whole season abandoned at episode five because something took the tab
away — into one retried episode. **The documented "close the tab to stop the run" gesture
survives**, because it lives outside that window: a tab closed while it sits there playing is
one this path never touches, and Ctrl-C ends a run at any time regardless.
