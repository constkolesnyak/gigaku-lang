# `lib/vocab/` — vocabulary tracking

The measured detail behind `import` / `plots` / `kanji` / `anki` / `words` / `publish` /
`backup` / `report`. The map — commands, shared layer, dependencies — is the repo-root
`CLAUDE.md`.

- `words.py` — the store: `Word` (text, language, stage, date), `merge(words, keep=())` (latest timestamp per (word, language) wins; a word whose latest stage is SKIPPED **leaves** the store — **except** for the keys in `keep`, which take their latest *tracked* state instead), the JSON cache, `import_words()` (LR + Migaku + `ankimorphs.py`), AnkiMorphs known-morphs export. The cache (`~/Library/Caches/gigaku/words.json`) is the **only** record of history — exports are deleted after import and neither source keeps a per-day history. It adopts polyglotka's identically-shaped cache once, automatically.
- `lr.py` — Language Reactor saved-items JSON → Words (five fields out of LR's huge item schema; phrases ignored).
- `migaku.py` — Migaku words, either from a CSV export or straight out of **Chrome's IndexedDB**. Migaku keeps its database (a gzipped SQLite blob) in **two origins** — the study.migaku.com site and its extension — and either can freeze while the other keeps syncing; the site origin did exactly that for nine silent days in 2026-07, so **both are always candidates and the freshest wins by the data's own clock** (`MAX(mod)`, sync cursor as tiebreak — never file size, never a trusted origin; `pick_source` is pure and pinned by `tests/test_migaku_chrome.py`'s end-to-end blob fixture). Each candidate also carries a **second clock, `last_contact`** — when that copy last reached Migaku's *servers*, read off three witnesses in the same blob: the Firebase token's `iat` (seconds, and stored as a **string** — an isinstance check that took only numbers dropped it silently), `localKeyValue['core.deviceMeta.lastSentAtMs']`, and `MAX(mod)` over `learningMaterial` (content Migaku pushes down: six Korean course rows landed in a bundle whose owner studies no Korean, 2026-08-18). It decides nothing here — the pick is still purely data freshness — and exists for `backup._staleness`, which cannot otherwise tell a week off from a dead sync; being evidence of *life* only, it can silence that alert but never raise it. Per origin the largest blob is the DB; inflate, `SELECT … FROM WordList`. An unreadable loser is skipped with a note; the winner is memoized per process and named in every note. Migaku's KNOWN/TRACKED/LEARNING/UNKNOWN/IGNORED map onto our KNOWN/LEARNING/SKIPPED — and **the last two are not the same claim**. IGNORED is "never show me this word again"; UNKNOWN is only "Migaku has met this word and you haven't marked it", the default state of everything it has ever parsed. Measured on Japanese, 2026-08-01: **2,386 UNKNOWN against 7 IGNORED**, so a SKIPPED from this source is overwhelmingly silence, not judgement — read as judgement it cost 190 words and an hour of hand-editing Migaku. The collapse is kept on purpose (it is the only signal that **un-learns** a word you set back to UNKNOWN), and the harm is fixed where the claims actually meet: `import_words` hands `merge` the whole AnkiMorphs known set as `keep`, so Migaku's silence can no longer delete a word Anki currently asserts. Without it the Japanese count drifts below Anki's every week, by however many words Anki learnt that Migaku happens to have seen. The blob→inflate→temp-SQLite→query path is shared by `read_chrome()` (the four-column store projection) and `dump_rows()` (the *whole* table, all statuses **plus the source**, for `gigaku backup`) via `_chrome_rows(sql)`.
- `ankimorphs.py` — the **third word source**, added 2026-08-01 because the report was truthfully saying nothing: Japanese read `+0 this week · last word 6 weeks ago` while being studied daily, since the cache only ever knew Migaku and LR and `words.save_known_morphs` was a one-way *export* into AnkiMorphs. It is a **plain merge** — every known morph becomes a word, deduplicated against the cache — and that is the second design. The first demanded **evidence**, a card the user had marked known or answered by hand, reasoning that most of AnkiMorphs' known set is gigaku's own reflection (3,099 of 3,797 lemmas come from the two files in `known-morphs/`, one of which this project wrote). The reasoning was right and the rule was still wrong: measured, it threw away **392 real words** (あっという間, おそらく, もう一度, それぞれ) that were in neither CSV and simply had no hand-marked card. **Rejected by the user — don't re-add a filter here.** What remains: **(1) Anki records no date for when a morph became known, so most words carry `words.UNKNOWN_DATE` (the year 1)** — `Morphs` is lemma, inflection and two interval columns, not one timestamp, and a review date does not exist either: of 462,487 cards, **12** have `prop:ivl>=1` and **16** have ever been answered; this collection is marked known by hand, not reviewed. Exactly one thing carries a believable date — the **305 cards the user actually touched** (`tag_known_manually`, or answered) — and a morph on one of those takes the earliest, which is 769 morphs. Dating the other 1,844 by the earliest `mod` of *any* card they sit on was tried and looked convincing (every morph dated, spread over seven working days) and is **junk**: a card's `mod` is when recalc last rewrote it, so "525 words on 22 July" only means "the user was in Anki that day", and for a morph on ten thousand cards it means nothing. Rejected by the user (2026-08-01): an obviously absent date beats a plausible wrong one. **Never date a morph from a card the user never touched.** The sentinel sorts before every real word and can never fall inside a report week; anything drawing a timeline must fold it into the left edge, which `plots.build` does — honouring it would stretch the axis back two thousand years and allocate a 740,000-day array per language. **Known consequence:** an undated word loses every `merge` tie, so 190 morphs that AnkiMorphs calls known and Migaku marks IGNORED now leave the store (they used to win on a July date), and the Japanese count reads 3,607 against Anki's 3,797 until those 190 are un-ignored in Migaku. AnkiConnect returns `mod` in **seconds for most cards and milliseconds for some** (`_when` normalises; unhandled, `fromtimestamp` raises on the year 58529). **Those dates are the only thing in a whole `gigaku backup` that ever needed Anki *running*, and since 2026-08-15 they no longer do** (`_evidence_dates`): AnkiConnect when Anki is up, `collection.anki2` read directly when it is not — which is precisely the moment the file is safe to read, since a shut Anki is what made the port refuse. The SQL is the two halves of `"tag:X" OR -is:new` (`cards.type != 0`, and `instr` on the space-**padded** tag — `_` is LIKE's wildcard and the tag is full of them), both verified against AnkiConnect's own answer on the live collection: 301 + 16 = **309, the identical set**, and a whole-collection read came back **11,179 words with zero differing dates**, in 0.3s against 0.7s over the wire. It is also **asked at all only when there is something to date**, which most nights there is not. Why it matters: from 2026-08-06 the 00:05 launchd job was wrapped in a shell script that did `open -jga Anki` whenever port 8765 was shut, so **Anki launched itself every night** — for one `findCards` query, over a set that on the whole known collection carries exactly **2** real dates. That wrapper is gone; the three plists call `gigaku` directly. Dating stays **best-effort at both ends** — an unreadable collection notes and returns `{}`, and an undated morph is a word this module already knows how to emit. **(2) The lemma→card join ignores inflection** — a lemma known through one inflection can be carded under another, and the lemma is what becomes a word. Measured, the looser join adds **0** morphs here, so it is correctness rather than coverage; the 1,184 with no card have none under either join. (An earlier note in this file credited it with those 1,184 — wrong, and the kind of claim worth re-measuring before repeating.) **(3) Nothing is filtered — the contract is that the counts agree.** `gigaku words --lang ja --stage known | wc -l` equals the add-on's `L:`, 3,797 the day it was built, and that is the user's requirement. Subtracting `removed-garbage.csv` was tried on the grounds that a "never show me this morph again" list is the opposite of knowledge: true, and it was exactly the 752 morphs standing between 3,045 and 3,797. Its content is now absorbed — `save_known_morphs` writes gigaku's known words *back* into that folder, so the imported garbage morphs are re-exported as known — and **the file itself was deleted at the user's instruction (2026-08-01)**; it survives in `vocab-backup`'s git history. The two sides converge on purpose. A morph **no card carries** (436 of them) gets `UNKNOWN_DATE` like every other undatable morph and is named in the run's note rather than stamped now — an earlier version of this entry claimed a fallback to the CSV's mtime; no such mechanism ever existed in the code, and the claim survived here for a week. **(4) A word the cache already holds is not re-emitted** — that is the dedup, and it is what keeps dates safe, since `merge()` takes the latest timestamp and re-sending a November Migaku word with a July card-mod would walk it forward and count it as new this week. A morph no card carries is **named in the run's note**, not stamped today. Live: 392 new words. `ANKIMORPHS_LANGS` (default `ja,de`, `""` switches it off) — a comma list since 2026-08-06, when German note filters joined the collection: a morph still carries no language, so **the lemma's script is the witness** (`_lang_of`: kana/Han/CJK-punctuation/the whole fullwidth block → `ja` — the db's 7 non-CJK known lemmas are fullwidth netspeak like ｗ and ｋｗｓｋ, measured; Latin incl. ä ö ü ß → `de`; a lemma no configured language claims is skipped and counted on its own note line, never guessed). Mixed scripts read as Japanese (Ｔシャツ is Japanese quoting Latin, never the reverse). Per-language counts are each script's share of the add-on's global `L:`, dedup and the `merge(keep=…)` shield are per `(word, lang)` key. **German lemmas are lowered at this boundary** (`_CACHE_FORM`): Migaku lowercases its German dictForms (ß preserved) and the cache carries ten months of them, while spaCy capitalizes nouns — measured, 5,308 of 7,290 drift by case alone — so lowering is what keeps the cache from growing an `Abend` beside its `abend`. The known-morphs CSV is the *opposite* boundary and keeps spaCy's capitals (a lowered row is inert for every noun at recalc): since 2026-08-06 `save_known_morphs` owns it for de too — the words go through `_de_lemmas` (subprocess into the AnkiMorphs spaCy venv, answers cached in `DE_LEMMA_CACHE`, so a daily run pays only for yesterday's new words — the claude-CLI no-new-dependency shape), `KNOWN_MORPHS_SAVE_LANGS='ja,de'` in the env, and `gigaku backup` refreshes both CSVs on every daily run so AnkiMorphs always sees today's Migaku knowledge. **The import recognises the CSV's own echo** (`_de_exported_forms`, 2026-08-08): the export writes capitalized spaCy lemmas, the read lowers them, and without the lemma cache's lowered keys ∪ values riding into `read_known` as already-represented, every lemma differing from its word returned daily as a new word at the year 1 — 594 fabricated words in three days, purged by `scripts/cleanup_de_words.py`; the lemma cache is that echo's record and must survive any cleanup. **On any normalisation failure the existing file stands** — the except-set covers what the subprocess path really throws (a dangling venv symlink is an OSError that once killed the whole daily backup), the write is atomic, an empty or >`BACKUP_SHRINK_PCT`-shrunken list refuses (a hollow CSV would unmark thousands of morphs at the next R, and `_gate` only guards the repo copy after Anki's is already overwritten), and a CSV frozen past `BACKUP_STALE_DAYS` joins the backup's stale alert (pinned by tests). Best-effort like Chrome, and `ankimorphs.db` is copied through SQLite's backup API before being read — the add-on may be mid-write. `collection.anki2` is read **without** that copy and only on the offline path above: it is 199 MB, the backup API costs 77s against 0.08s for the query itself, and nothing is writing to it (that is why AnkiConnect refused). `mode=ro`, never written. `tests/conftest.py` switches it **off for every test** by default: unlike the other sources it has no export file to find, so it would reach the user's live Anki from any test that calls `import_words()`.
- `kanji.py` — kanji ranked by known-then-learning word counts; TSV or an Anki query. `\p{Han}` is done with codepoint ranges (that's the whole reason `regex` isn't a dependency).
- `plots.py` + `plots_page.html` — daily cumulative counts per (language, stage) → one **self-contained HTML file**, no server. All drawing is hand-written SVG in the page: lines (monotone-cubic, so a cumulative curve can't overshoot into a dip that never happened), crosshair + tooltip, legend toggles, drag-to-zoom, stat tiles with sparklines, per-language known-vs-learning panels, a month-end table, light/dark, Save PNG. Second tab: the **kanji table** (payload reuses `kanji.collect()`, so page and TSV can't disagree), filterable by character or by any word containing it; absent entirely when there's no Japanese. Colours come from `lib/pages.py`'s validated palette **via the payload** (`DATA.palette` — the page carries no copy); `_slots()` places reserved languages (`LANG_SLOTS`) *first* so a stray language can never repaint the others. The page is read mostly from a phone, and behaves like it: `touch-action: pan-y` (a finger on the chart scrolls the page; drag-to-zoom reads only horizontal movement), tap-away/`pointercancel` clear the crosshair a touch leaves stuck, and range/stage/hidden-languages/tab/theme persist in `localStorage` (zoom deliberately transient). Theme is a three-state toggle — Auto → Light → Dark, Auto default (the old "macOS already has a switch" philosophy as the default, not the law).
- `publish.py` — `gigaku publish`: render (plus the report pages, see `report.py`) → `rsync -az --delete` into `PUBLISH_DIR`. With `PUBLISH_HOST=""` (the default) that is a **local copy into `PUBLISH_DIR`**, which a small static server on the same machine serves at `PUBLISH_URL` — bound to the Mac's tailnet IP, so **tailnet-only** by port binding (the kanji table lists real words). The serving side is not part of this repo; any static file server will do. Setting `PUBLISH_HOST` to an ssh name brings back the old push-to-a-server shape (the retired Pi ran that way). `--delete` means the staging dir must assemble *everything* published. The launchd story since 2026-08-08: `com.gigaku.backup.plist` snapshots at 00:05 (just past midnight, so the weekly report's Monday-Sunday window reads whole days — the why lives in that plist's own comment), `com.gigaku.publish.plist` publishes at 01:05 — one hour after the backup, one story instead of two clocks — and `com.gigaku.publish-trigger.plist` publishes on demand the second the report host drops a trigger file. The old `com.gigaku.report.plist` is gone: the weekly report runs on the report host off the backup snapshot (`gigaku report --from-backup`). **The Mac must be the one that gathers**: the cache is local and Migaku's words live in *Chrome's* IndexedDB, which no web page can read (same-origin policy) — a hosted page cannot fetch them itself, so don't "improve" this into a pull.
- `backup.py` — `gigaku backup`: a daily, versioned, **off-site** snapshot of the three datasets that exist in exactly one place, committed as plain text to a git repo (`BACKUP_DIR`, default `~/vocab-backup`) and pushed to `BACKUP_REMOTE` (a **private** GitHub repo — the CSVs list every word you know). What's irreplaceable and why the backup, not a re-import, is the only recovery: **(1)** the word cache (`words.json`) is the sole per-day history — LR/Migaku exports are deleted after import and neither service keeps a history; it's also **excluded from Time Machine** (everything under `~/Library/Caches` is). **(2)** Migaku's *full raw* `WordList` — `dump_rows()` keeps **every** status including the UNKNOWN/IGNORED rows the store drops as SKIPPED, i.e. the "never show me this word again" curation, which lives nowhere but Chrome's IndexedDB. **(3)** AnkiMorphs' hand-curated CSVs — AnkiWeb syncs the *collection*, not add-on data. (`removed-garbage.csv` was the prize exhibit here and is **gone**: its morphs were absorbed into the word cache and the file deleted, 2026-08-01. It is still in this repo's history, which is the point of a versioned backup.) The design is **stage → gate → swap**: everything is gathered into a temp dir, the `_gate` refuses to commit if any dataset is empty or shrank past `BACKUP_SHRINK_PCT` (default 10%; `--force` overrides), and only then are the managed paths (`words.json`, `migaku/<lang>.csv`, `ankimorphs/…`, `manifest.json`) swapped into the repo — so a logged-out Chrome or a wiped language can never overwrite a good backup with a hollow one; the previous commit just stands and the log says which dataset shrank. Migaku rows go to **per-language, sorted** CSVs (a single 44k-row file would churn wholesale; sorted per-language files diff to a few KB). A `.gitattributes` of `* -text` is dropped in so git stores bytes verbatim (no CRLF↔LF churn, no phantom diffs). `_commit` skips the commit entirely when nothing changed (a slept Mac won't stack empty commits) and `_push` runs **after** the local commit is safe (a GitHub outage leaves an unpushed commit, loses nothing). Reuses `import_words()` (non-consuming) to refresh first, exactly as `publish` does. **A bad run alerts Telegram directly** (`_alert`, via `lib/telegram.py` — same bot and env file as `gigaku report`; the retired Pi heartbeat/watchdog is gone): `failed` (crash or failed push — and a **non-UserError crash alerts too**, the catch-all exists because an `OSError` used to propagate with no alert anywhere), `refused` (the gate), or `stale`. **Stale is the gate's blind spot made visible**: a frozen-but-readable Migaku source produces the same counts day after day, exactly like a quiet week — the measured nine-day freeze — so a frozen chosen origin still commits (the other two datasets are healthy; the source is Chrome's problem) but says so, daily, until it heals. **It takes two clocks, and needs both stopped**, because `MAX(mod)` alone cannot tell a holiday from a dead extension and on its first firing ever (2026-08-19) it got that exactly backwards: five days with no word marked, alert sent, while the same blob showed the token re-minted at 00:53 that morning and Migaku's Korean course content pulled the evening before — nothing was lost and the message said words were. So it fires only when the chosen origin's `MAX(mod)` **and** its `last_contact` (`migaku._contact`: token `iat`, the extension's heartbeat, content pushed down — see `migaku.py` above) are both older than `BACKUP_STALE_DAYS` (default 5), and then it names the *sync* rather than the words. Frozen words under a live sync is silence: an alarm that goes off every holiday is one you learn to swipe past, which costs precisely the freeze it exists to catch. A bundle with no contact clock at all is judged on the data clock alone — a witness we cannot hear is not an alibi. A healthy run is silence; the case "the job stopped running at all" can't alert by definition, and it is now **unwatched** — the weekly report used to carry `backup: N days ago` as the check on the checker, and the user removed that line (2026-08-01). Failed/refused/stale still alert. `manifest.json` records `migaku_source` (origin kind, profile, `max_mod`, sync version, `last_contact`), giving the repo history a per-day answer to "when did this go wrong" — and, since the contact clock is in there too, to "was it ever syncing". A `.gitignore` of `.DS_Store` is dropped in beside `.gitattributes` (`git add -A` once swept one in).

- `report.py` + `report_card.html` — `gigaku report`: **the week just gone, pushed to Telegram** as one picture — a chart panel per language, stacked — captioned with the week in words. `publish` puts the numbers behind a URL you have to remember to open; this is the other direction, and the two share their data, their palette and their idea of which languages count. Four things it is built around. **(1) The week is what the data can say**: a word carries only the date its stage was *last* modified (same caveat as `plots`), so "+258 this week" is "258 words whose current stage is KNOWN and which last moved in the last seven days" — hence `new`, never `learnt`. Weeks are counted back from **today**, not snapped to a calendar Monday: the report fires on whatever day the schedule fires, and "the last seven days" is the span the reader actually lived. **(2) A quiet week is a result.** It prints `+0`, draws a 3px stub where the bar would be (nothing at all reads as missing data), always labels the last bar even at zero, and says `last word 10 days ago`. A notification that only arrives with good news is one you stop believing. **The message says this week and nothing else** — `▸ N known · +N this week · +N kanji` and `▸ last word <when>`, per language: the week before, the four-week average and the standing kanji total were dropped by the user's decision (2026-08-01) as history the card already draws, competing with the one number the report is about. `last word` runs on **every** language, not only the quiet ones — it is what tells a `+0` from a broken pipeline, and only a line that is always there can be read that way. **The card was stripped to a header and one chart the same day**, in three steps and in this order: the bar chart's title, then the bar chart whole, then the stat row. Between them they said the same thing four ways — the week is `+215` in the header, a shaded band at the end of the curve, and the rise from where the curve entered that band to its labelled endpoint. What the tiles carried that a picture can't show (week before, four-week average, kanji count) went for the same reason it went from the message: history, not news. `weeks` and `prev` stay in `build()`'s payload and are now rendered by nothing — `--weeks`/`REPORT_WEEKS` shape data no reader sees, which is worth removing the next time this file is opened. **(3) Every number is computed once, in `build()`** — the card renders it and the message quotes it, so the picture and the text beside it cannot tell two different stories about the same week (the `plots._kanji` failure mode arriving through two renderers instead of two commands). **(4) A chart that is a picture has no hover layer**: every number is in the header or direct-labelled on the mark — each curve's endpoint, `+N this week` in the header, the shaded band marking the week. **Every language shares ONE coordinate system** (user's decision, 2026-08-01): one x, one y, one curve each. Curves on separate axes are separate charts wearing one frame, so the frame is real — `build()` emits a single `chart` object and the page draws it. The header *is* the legend (a language's name in its own curve's colour), the area fill is gone (two translucent areas overlapping invent a third colour that means nothing), and end labels are pushed apart by `spread()` so two curves finishing close together don't print over each other. The window is a **rolling `CHART_DAYS` (30)** back from today, clamped to the history that exists — the full curve spent nine tenths of its width on years the report is not about — and a curve inside it still carries its pre-window total as its baseline, or the chart would claim the count restarted a month ago. **The message is shaped after a weekly post the same bot already sends** (same reader, and the user asked for it by name): a bold title carrying the site link, the span under it, then one blank-line-separated block per language — bold `🇩🇪 German`, one fact per `▸` bullet — and the backup line last. **One fact per bullet**: `2,350 known · +0 this week` was two facts wearing one, and was split by the user's decision (2026-08-01). Numbered headings (`𝟭 ·`, mathematical-bold glyphs) were tried the same day and removed the same day — with the flag and the language name already on both the block and the card, the numeral tied together two things nothing had untied. Languages default to whatever `PLOTS_HIDDEN_LANGS` doesn't hide (English is a 10k dump, French is finished — neither is news), so that judgement lives in one place; `REPORT_LANGS` overrides. Colours are `lib/pages.py`'s dark palette row indexed by the same `LANG_SLOTS`, so German is the blue the page taught you. **Rendering is headless Chrome, not a fourth dependency** — the project already requires Chrome everywhere else, and the alternative was Pillow or matplotlib to draw two shapes. The measured catch: Chrome **writes the PNG and then does not exit** (both `--headless=old` and `--headless=new`; the file is complete in ~1s and the process is alive 45s later), so the process is never waited on — the file is the signal, its trailing `IEND` chunk is the receipt that it is finished (a size that stopped growing is not: a slow disk fakes that), and the process is killed the moment the receipt is in. It gets a scratch `--user-data-dir`, because the user's Chrome is running and a second Chrome on one profile refuses to start. Credentials are **deliberately not Settings fields** — `gigaku info` prints every setting, and a token that can be printed ends up in a log — so they live in `TELEGRAM_ENV_FILE` (`~/.config/gigaku/telegram.env`), env first. **One notification, not two** (user's decision, 2026-08-01): all the languages are stacked into a **single** PNG — `render_card` lays out one 1000×700 `.card` per language and `shot` takes the window at `700·N`, so the merge costs a taller screenshot rather than Pillow to paste bitmaps — and it goes as one `sendPhoto` with the message as its **caption**. It was an album then a separate message, because a caption caps at 1024 characters; the message is now a dozen short lines, so `_tg_len` (tags stripped, UTF-16 units — Telegram's own measure) checks it fits and the old photo-then-message shape stays as the fallback for the day it doesn't. The card carries **no date span**: the caption says it once. Telegram transport (`credentials`/`tg_call`) lives in `lib/telegram.py`, shared with the backup's alerts. Every run (dry included) additionally writes the week as a **site page** (`site()` + `report_page.html` → `REPORT_SITE_DIR`: `<date>.html` per week, `index.html` the latest, cards inlined as data: URIs), which `publish` copies next to the chart page. `--from-backup` reads `BACKUP_DIR/words.json` instead of the live cache — the same dataset one commit behind — which is also how any past week's page re-renders after a cache wipe.
