# `chrome/gigaku/` — the MV3 extension that hands the ripped subs to Migaku

Engineering notes; `chrome/gigaku/README.md` is the user-facing half. The map is the
repo-root `CLAUDE.md`.

- `chrome/gigaku/` — a small MV3 Chrome extension (load-unpacked) that hands the ripped SRT pair for the Netflix episode you just opened to **Migaku**, into its *Target Subtitles* / *Secondary Subtitles* slots, so an episode starts with both tracks loaded instead of two file pickers. The library lives at `chrome/gigaku/subs/` — **inside** the extension on purpose: an extension can `fetch()` its own files, which is what makes this work with no local server, no `file://` permission and no folder picker (gitignored; `gigaku subs`/`gigaku srt` write straight into it via `SRT_TARGET_DIR`). An extension can't *list* a directory, so `lib/subs/library.py` keeps `subs/index.json` beside the files; matching goes **Netflix video id** (from `/watch/<id>`, recorded per episode by `gigaku subs` — exact, locale-proof) → title+season+episode → plain path guess, so hand-copied files work too. Two ways to feed Migaku, both measured against its bundle: its **two hidden `.srt` file inputs** (reachable because `#MigakuShadowDom` is an *open* shadow root; the handler selects the file into that exact slot and resets `input.value`, which is the receipt that it was consumed) and, if those aren't mounted, the **synthetic `drop`** its `DragAndDropZone` deliberately accepts (`evt instanceof CustomEvent && Array.isArray(evt.detail.types)`) — that one can't pick a slot, so the files get a `.de`/`.ru` suffix and Migaku sorts them by filename. Netflix's series title is `videoMetadata[k]._metadataObject.video.title` (**not** `_video.title`, which is undefined) — read by the `world: "MAIN"` content script, since a page global is the one thing an isolated content script can't see. **That MAIN-world half also picks the German soundtrack** (`audio` alongside `meta`, both answering `{cmd, nonce, data}` where a null `data` means *ask again* — the player boots long after the script does): everything here is watched dubbed, and Netflix's memory of that choice is per profile **and per title**, so a show it has never played in German opens in the original. It goes through Netflix's **own player API** — `getAudioTrackList`/`getAudioTrack`/`setAudioTrack`, never the on-screen menu, so a redesign or an interface language can't break it — and is a **read before a write**, because re-selecting the track already playing still costs an audible re-buffer; an episode already in German is left alone. `PRIMARY` wins, so a German *audio-description* track can never beat the plain dub. The player is resolved **by the URL's movie id, never `getAllPlayerSessionIds()[0]`** (same stale-session trap as `lib/subs/subs.py::_PLAYER`), and a closed session is *deprioritised rather than skipped* — measured on a live playing episode, `isVideoPlayerClosedForSessionId` answered **true** for the one and only session whose `getMovieId()` matched the URL, so requiring an open one finds no player at all. It deliberately **does not touch the badge** (that is a claim about the subtitle hand-off, and a title with no German dub is nobody's failure) and is not waited on, so a missing pair or an absent Migaku can't cost the episode its soundtrack; the outcome goes to the console. Measured live (2026-08-04): forced to English, the shipped pass answered `{state:"set", was:"English", track:"German"}` and the re-read confirmed `already`. Once per episode, never watched — the same rule as the visibility pass. **The badge is a claim, so it is earned**: `✓` means Migaku's two dropdowns were *read back* and name our files, not that the files were handed over. Migaku's file handler is read-FileList → parse → select-into-slot, and it is the **read** that resets `input.value` while both later steps give up silently — so the old reset-as-receipt lit `✓` green over a switched-off Migaku that had loaded nothing. The real receipt is each slot's dropdown label, which is bound to the player's `targetSubtitleData`/`secondarySubtitleData`. **That receipt is waited for after feeding and is never a precondition of it** — a slot is a control container with a **file input**, not one with a dropdown. Migaku renders the input unconditionally but the dropdown only when `(that slot's filtered options > 1) && targetSubtitleData !== undefined`, i.e. only once it *already* holds a usable track; on the episodes this extension is for — no subtitle in the language being learned, which is the whole reason the track was ASR-ripped — it shows "none available" instead, forever. Requiring two dropdowns before feeding therefore refused the good path in exactly that case and fell through to the blind drop, and Haikyu!! S01E01 came back as `?` over an episode the inputs would have loaded. Registering our file is what puts the second option in that list, so feeding is what makes the dropdown appear at all. A failed hand-off also **prints its trace as text, not as an object**: chrome://extensions' Errors page flattens every console argument with `String()`, so the one line whose job is to name the hook that moved read `[object Object]`, and a `sent` badge said nothing about which of the four hooks it died on. `panelState()` adds what the panel was showing (input/dropdown/spinner/none-available per container) whenever there was nothing to feed. Those dropdowns live in Migaku's lazily-mounted video-options popover, so the extension **opens it itself** — a **non-bubbling** synthetic click (the popover's click-away listener is on `document` and a bubbling click re-closes it instantly) on the button found by its **ClosedCaptions icon path**, not its label, so an interface-language change can't break it — feeds, verifies, closes. Three attempts. **Loaded is not shown, and `✓` claims both.** Migaku hides a track it has loaded through three settings it keeps **per learning language, not per video**, so one keypress or one study preset outlives by weeks the episode that set it and every episode after opens with both files in their slots and nothing on screen: the two "Always hide …" switches (`hideTargetSubtitles`/`hideSecondarySubtitles`, what `w`/`shift+w`/`r` toggle); `playMode.type`, where — read off `PLAY_MODE_PRESETS` — **five of the eight presets obscure on purpose**, primed listening hiding *both* (secondary until you pause) and intensive reading / intensive listening / show-on-pause / one-T hiding until their reveal condition fires, leaving only *default* and *intensive hybrid* showing both outright; and `playMode.custom.obscuring.{target,secondary}.effect`, the one the preset row cannot answer because it applies exactly when the preset **is** custom — hence the row is consulted only when the custom panel isn't there to consult instead. So every feed ends by putting all three back, in the popover it already has open. Each is **read before it is written** (a Migaku already set right is never clicked — on almost every episode the pass touches nothing), and each write is confirmed by a class Migaku binds to its own store — `-toggled`, `--active`, `aria-checked` — never by the change we just made to the control, which is the same distinction the feed draws between Migaku *reading* a file and Migaku *loading* it. The toggle is **set, not clicked** (`input.checked = false` + `change`): a click bubbles to the `document` click-away listener that closes the popover out from under the rest of the pass, the same trap `poke()` exists for; the preset is poked non-bubbling and aimed by the **Default mode's icon path**, so a reordered row can't make it click the wrong mode. The final receipt is Migaku's own `-hidden`, which it puts on each track's list in the subtitle overlay the moment *anything* takes it off screen — one reading covering all three settings, needing no panel open; a list that isn't there reads unknown, never hidden. Measured live against the running extension (2026-08-03): flipping the switch moved `-toggled` and the overlay's `-hidden` together, and poking Default moved `--active` and made the custom rows vanish, both restoring exactly. **The whole pass is gated on German** (`SHOW_FOR_LANG`), and that gate is the point rather than a caution: these settings are per *learning language*, everything here rips German-with-Russian pairs, so German is the only language whose "show both tracks" this extension has standing to assert — and the language it would otherwise reach into is **Japanese, which runs Primed Listening, a mode whose entire purpose is hiding both tracks until you pause** (user's decision, 2026-08-03: the feature is German-only and Japanese stays as it is). The language is read from `data-mgk-lang-selected`, Migaku's **own published attribute** (`ATTRS.LANG_SELECTED`, read back by its own page bridge) rather than a flag icon or a guess; unreadable counts as not ours, and on any other language a good feed still goes green exactly as before, because the hand-off is what the badge answers for. What it deliberately does **not** do is fight for it mid-episode — a `w` pressed while watching is a decision about this minute, and the next episode is where "show me both tracks" starts again — so the pass runs once per episode, with the feed, and never watches. Remaining badges: `–` no pair, `?` fed through the drag-and-drop path which confirms nothing, `H` loaded but Migaku would not un-hide a track, `!` refused, `M` Migaku isn't running here, `A` Migaku's app window stayed shut. **Clicking the icon fixes the last five**: with the `management` permission the worker can tell "switched off in Chrome" from "never loaded into this page", and a click switches Migaku on (Chrome prompts — an extension may never do that silently; `setEnabled` must therefore be the **first** call in the click handler, because a service worker keeps the click's user gesture only until its first `await`) and reloads, or reloads, or just re-feeds. **Migaku's app window is the precondition for all of it**: its toolbar renders only when `isLangReady && isAppWindowOpen && isDomainEnabled`, so with that window closed there are no dropdowns and no file inputs at all — the state the old green tick was lying about. `isAppWindowOpen` is set by the app window's own page (`created(){ this.isAppWindowOpen = true }`), which Migaku ships as a web-accessible resource, so when the toolbar is missing the worker opens `pages/app-window/index.html` itself and the page waits for Migaku to come up (`tabs` permission, only to check one isn't already open — Migaku's app window detects a duplicate and answers by setting the flag back to *false*). That page *is* "Migaku being on" in daily use; switched off in `chrome://extensions` is the rarer case and the only one needing a click. It gets a **window of its own, unfocused**, and that window is not negotiable: the same page as a pinned background tab animates nothing and steals no focus — tempting, because on macOS a new window is animated in *and* both focus changes are animated too, since Migaku **pulls focus to it itself** (its `requestShowAppWindow` defaults to `focusWindow: true`, fired when `isAppWindowOpen` turns true) and nothing passed at creation prevents that — but **Chrome throttles timers in a hidden tab and Migaku comes up broken; measured, don't retry the tab.** A second of animation is the price of Migaku working. Focus is handed back, not fought for: for 8s an `onFocusChanged` guard returns focus to the episode's window whenever that one window takes it, countering nothing else so a deliberate click still sticks.
